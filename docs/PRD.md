## 1. 产品概述

### 1.1 一句话定位
一款**单机桌面工具**：用多 Agent 协作把公众号文章从选题写到定时发布，但每一个 AI 产出都必须经人工放行——"AI 干活，人拍板"。

### 1.2 目标用户
- 首发用户：本人（个人公众号运营者，有 AI API Key，不愿租服务器）
- 泛化用户：1-2 人运营的内容号作者，重视"活人感"胜过产量

### 1.3 核心价值（按用户明确优先级排序）
1. **活人感**：文本去 AI 味 + 个人素材注入 + 排版避免模板感——最重要
2. **配图质量**：图在语义节点出现、契合主题、位置不突兀、来源不限（AI 生图/网图/截图）
3. **零服务器**：定时发布、密钥保管、热榜抓取全部在本地完成
4. **人在回路**：AI 永远产出"建议"，人逐条放行，绝不整篇重写

### 1.4 不做什么（Non-goals）
- 不做云端多端同步、不做协作、不做账号矩阵群发
- 不做粉丝互动/评论管理/数据分析（公众号后台已够好）
- V1 不做手机 App（V2 走"桌面开局域网服务 + 手机浏览器写草稿"路线）
- 不做绕过平台规则的批量营销号功能

## 3. 功能需求

优先级：P0=没有就不是产品；P1=第一个可用版本应有；P2=增强。

### F1 选题台（P1）
- 本地内嵌 DailyHot 热榜（微博/知乎/抖音等），支持手动刷新与降级（抓取失败时粘贴链接）
- 关键词 → 选题 Agent（热榜聚合 + 联网搜索 API）→ 3-5 个候选话题：标题+切入角度+来源证据
- "我的选题"卡片池：采纳→创建工作台草稿；不采纳→沉底
- **HITL**：AI 选题永不自动占位，全部待采纳

### F2 编辑器（P0）
- Markdown 源码编辑（左）+ 公众号样式实时预览（中），双向同步
- 段落块列表：拖拽排序、"回炉"旗标（AI 只处理旗标块）、人写/AI 稿标签
- 主题渲染：至少 3 套内联样式主题（复用 doocs/md 思路），一键切换
- 自动保存 + 每次应用 AI 建议生成快照，支持按段回退
- **验收**：打字→改→存→渲染→复制进微信编辑器不掉格式

### F3 AI 建议系统（P0，人在回路核心）
- 选区浮动工具条：更口语/缩短/展开/去AI味/换例子/自定义要求
- 建议卡片：原文删除线 vs 新文绿字 diff；仅两个写操作【应用到该段】【忽略】
- 应用后：目标段落高亮动画 + toast 带【撤销】
- **硬性约束**：不存在任何"作用于全文"的 AI 写操作；初稿生成绕开人写段落
- 接口协议：AI 返回结构化 JSON `{target, old, new, reason}`，前端校验 old 与选区匹配才允许应用

### F4 多 Agent 流水线（P1）
- 7 个角色：选题→调研（联网检索+网页截图取证）→写作→回炉→配图→去味→审核（事实/版权/敏感词）
- 编排：本地状态机（每 Agent = 角色 prompt + 结构化输出），上下文显式传递，任一 Agent 失败可单独重跑
- 每个 Agent 的产出都是建议卡片队列，人放行后流水线才推进（Agent 间自动、Agent→人之间设卡）
- 审核 Agent 报告为 P0 子集：至少做"外链图片检测 + 敏感词表检测"

### F5 配图地图（P1）
- 槽位数据结构：`{位置块id, 意图描述, 提示词, 候选图[], 来源类型, 状态}`
- 三来源：
  - AI 生图：用户自带文生图 API（提示词可见可改，重新生成）
  - 网图搜索：搜索 API（博查/Serper 类）→ 候选+原网页链接；**版权风险提示为强制 UI**，未确认不可入发布件
  - 网页截图：本地无头浏览器截取（自动打码用户名/头像），支持框选区域
- 全部槽位确认前，发布队列对该文章锁定

### F6 去 AI 味 + 个人素材库（P1，活人感核心）
- 素材库：本地 YAML/JSON 条目（经历、口头禅、观点立场、常用案例），可增删改
- 去味改写：规则清单（拆排比/删套话/句长参差）+ 素材注入；引用了哪条素材在卡片上标注
- AI 味评分：规则打分（句式统计+套话词表）为主，LLM 评估为辅；分数只做趋势提示，不做拦截

### F7 发布与定时（P0）
- 链路：正文本地图→uploadimg 转 CDN→首图/封面→add_material→draft/add→freepublish/submit→轮询发布状态
- 定时：本地调度器（托盘常驻，20s tick）；App 未运行时由 Windows 计划任务拉起无头命令补发
- **默认发布门**：到点→推草稿→系统通知→人在队列点【确认发布】才调 freepublish（可在设置关闭，不推荐）
- 失败处理：错误码翻译成人话（40164→白名单指引+复制 IP 按钮；48001→权限降级说明）；自动重试 ≤3 次
- 降级路径：无 freepublish 权限的号 → 只自动到草稿箱，人手动群发

### F8 设置与凭据（P0）
- AI 服务：baseUrl/key/model（OpenAI 兼容）、文生图服务、搜索 API key
- 公众号：AppID/AppSecret + **连通性自检**（token→草稿权限→发布权限 三步逐项报结果）
- 安全：密钥用 Electron safeStorage（Windows DPAPI）加密，不落明文；日志脱敏
- 调度：托盘常驻开关、计划任务注册、发布前提醒时间、公网 IP 探测显示
- 数据：本地目录、素材库入口、Markdown 导出

### F9 本地数据（P0）
- 存储：V1 用 JSON 文件（已实现），M2 迁 SQLite（better-sqlite3）——见开放决策 D2
- 实体：Article / Block / Slot / Suggestion / QueueTask / MaterialEntry / Snapshot
- 快照：每文章保留最近 50 版

## 4. 信息架构与界面规范

```
窗口（工具形态，非网页）
├─ 标题栏：状态胶囊（公网IP/白名单、调度器）· 设置按钮
├─ 左侧图标导航：选题台 / 工作台 / 配图地图 / 发布队列
├─ 选题台：搜索条 + 热榜流 + 我的选题
├─ 工作台三栏：块列表(旗标) | 可编辑预览(选区→AI) | Agent流水线+建议卡片
├─ 配图地图：槽位卡（上下文+提示词+三来源切换+确认门）
├─ 发布队列：时间线卡 + 失败详情 + 确认发布按钮
├─ 设置弹窗：AI服务 / 公众号 / 发布与调度 / 数据
└─ 状态栏：本地库统计 · API连通 · 密钥状态
```

**HITL 五铁律（全局约束，违反即 bug）**
1. AI 产出=建议，人放行才生效；2. 修改粒度人圈定，无全文重写；3. 人给意图 AI 给结果（自定义要求）；4. 关键节点审批门（配图逐张、发布最终确认）；5. 每步可回退（快照）。

## 5. 技术架构

```
Electron 主进程 (Node)                    渲染进程 (无框架，V1)
├─ lib/wechat.mjs   微信API客户端          ├─ 编辑器（textarea+块同步）
├─ lib/ai.mjs       OpenAI兼容客户端       ├─ 预览（主进程渲染HTML回传）
├─ lib/md2wechat.mjs 主题渲染引擎          ├─ 建议卡片/选区工具条 UI
├─ lib/scheduler.mjs 定时调度              └─ 队列/设置表单
├─ lib/store.mjs    JSON持久化
├─ safeStorage      密钥加密(DPAPI)
└─ Tray/Notification/单实例
```
- **为何 Electron 而非 Tauri**：本机无 Rust 工具链，Electron 当天可跑通；核心库全部纯 JS，将来平移 Tauri 成本主要在壳层（见 D5）
- 手机 V2：主进程加局域网 HTTP 服务（仅同一 Wi-Fi），手机浏览器写草稿→同步到本地库；发布仍由桌面执行

## 6. 约束与风险（诚实清单）

| 风险 | 等级 | 缓解 |
|---|---|---|
| 未认证订阅号无草稿/发布 API 权限（48001） | **高，决定产品形态** | M0 先跑 `npm run check` 自检；无权限则降级"工具到草稿+人工群发" |
| 家宽 IP 变动导致白名单失效（40164） | 高（日常摩擦） | 启动探测+状态栏常显+失败一键复制 IP；无法根治 |
| 正文外链图片被微信过滤 | 中 | 发布前强制转存（已实现于 buildDraftPayload） |
| 网图版权 | 中 | 强制来源标注+确认门；文档明示风险自担 |
| 微信无定时发布 API | 已确认 | 本地调度器方案；电脑关机即失效→UI 显著提示 |
| uploadimg 限额（约100张/日） | 低 | 队列合并去重、失败重试限 3 次 |
| Playwright 体积（截图功能） | 低 | 可选安装，非核心路径 |

## 7. 里程碑

- **M0 地基验证（0.5 天）**：`check-wechat.mjs` 验证账号 API 权限 → 决定完整/降级形态
- **M1 核心闭环（1-2 周）**：F2 编辑器 + F3 建议系统 + F7 发布链路（手动送草稿/发布）+ F8 设置——**能写、能 AI 改选区、能真发**
- **M2 定时与持久（0.5-1 周）**：调度器+托盘+计划任务+失败报错；SQLite 迁移（若定）
- **M3 活人感（1 周）**：F6 素材库+去味+评分；F4 流水线（先接写作/回炉/去味三个 Agent）
- **M4 配图体系（1-1.5 周）**：F5 三来源 + 调研 Agent 截图 + 审核 Agent 报告
- **M5 选题台（0.5 周）**：F1 DailyHot + 选题 Agent
- **V2 手机（另立项）**：局域网写作端

## 8. 成功指标（自用版）
- 一篇文章从选题到进草稿箱 ≤ 40 分钟
- 定时发布成功率 ≥ 95%（开机条件下）
- 自己读回改后文本时"这像我的话"比例显著高于裸用 ChatGPT（主观但为一票否决项）
